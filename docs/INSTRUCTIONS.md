# QDMouse4M Benchmark Code

Code package for preparing QDMouse4M pose-estimation benchmark data, training
SLEAP and Lightning Pose 3D baselines, running inference, and computing the
benchmark metrics.

Point the code at the dataset with:

```bash
export QDMOUSE4M_RELEASE_ROOT=/path/to/qdmouse4m_release_neurips_v1
```

## Environment

Install with `uv`:

```bash
uv sync --extra sleap --extra lp3d --extra dev
source .venv/bin/activate
```

LP3D uses Lightning Pose, whose NVIDIA DALI dependency is platform-specific.
Install it inside the same environment on a CUDA Linux machine:

```bash
INSTALL_LIGHTNING_POSE=1 bash scripts/setup_uv.sh
```

If your machine requires a custom CUDA-enabled PyTorch wheel, install that into
the same `uv` environment following your local hardware instructions.

## Data Layout Expected

The release root is expected to contain:

```text
sessions/session_<id>/
  labels/keypoint_annotations.npz
  sam3_dynamic_bboxes/bboxes_<view>.csv
  calibrations/camera_calibration.toml
  videos/refonly/<view>.mp4 or <view>.avi

training_subsets/refonly_pose_k50_v1_valid3dfix_20260503/
  subsets/<train_split>/selected_timepoints.csv

evaluation_sets/refonly_pose_k50_in_session_v1_valid3dfix_20260503/
evaluation_sets/refonly_pose_k50_outsession_v1_valid3dfix_20260503/
  subsets/<test_split>/selected_timepoints.csv
```

The core split manifest is `selected_timepoints.csv` with columns:
`pool_index, source_index, cluster_id, cluster_sample_rank, session_id,
frame_idx, valid_3d_keypoints, valid_2d_points`.

## Prepare Model-Ready Projects

First materialize the shared refonly dynamic-crop image pool from the released
videos and SAM3 dynamic bboxes:

```bash
qdmouse4m materialize-images \
  --dataset-root training_subsets/refonly_pose_k50_v1_valid3dfix_20260503 \
  --split train_0050 \
  --split train_0100 \
  --workers 6
```

Then create LP3D/SLEAP project folders from the materialized image pool and
canonical labels:

```bash
bash scripts/prepare_lp3d_projects.sh \
  training_subsets/refonly_pose_k50_v1_valid3dfix_20260503 \
  train_0050 train_0100 train_0500 train_1000 train_5000 train_10000

bash scripts/prepare_sleap_projects.sh \
  training_subsets/refonly_pose_k50_v1_valid3dfix_20260503 \
  train_0050 train_0100 train_0500 train_1000 train_5000 train_10000
```

The helper scripts can run both stages by setting `MATERIALIZE_IMAGES=1`.

## Train LP3D Models

Run the full small-split matrix:

```bash
WORK_DIR=outputs/lp3d \
SPLITS="train_0050 train_0100 train_0500 train_1000 train_5000 train_10000" \
BACKBONES="dino dinov2 dinov3" \
SEEDS="0 1 2" \
bash scripts/run_lp3d_experiments.sh
```

Run one LP3D job directly:

```bash
qdmouse4m train-lp3d \
  --project-dir "$QDMOUSE4M_RELEASE_ROOT/training_subsets/refonly_pose_k50_v1_valid3dfix_20260503/lp3d/train_0500" \
  --output-dir outputs/lp3d/train_0500/dinov3/seed0 \
  --backbone dinov3 \
  --seed 0 \
  --resume
```

Default LP3D recipe: 80/20 train/validation, 256 px model resize, DINO/DINOv2/DINOv3
ViT-S backbones, no temporal loss, no PCA multiview loss, no supervised
reprojection loss, no 3D image augmentation, and early stopping after the minimum
epoch floor.

## Train SLEAP Models

SLEAP-NN requires a single-instance YAML template. Use a template generated by
your installed SLEAP-NN version and pass it via `SLEAP_TEMPLATE`.

```bash
SLEAP_TEMPLATE=/path/to/single_instance_template.yaml \
WORK_DIR=outputs/sleap \
SPLITS="train_0050 train_0100 train_0500 train_1000 train_5000 train_10000" \
BACKBONES="unet convnext swint" \
SEEDS="0 1 2" \
bash scripts/run_sleap_experiments.sh
```

## Inference And Evaluation

Run LP3D inference and metrics:

```bash
bash scripts/run_lp3d_eval.sh \
  outputs/lp3d/train_0500/dinov3/seed0 \
  "$QDMOUSE4M_RELEASE_ROOT/evaluation_sets/refonly_pose_k50_in_session_v1_valid3dfix_20260503" \
  test_100000_stratified \
  outputs/eval/in/lp3d/train_0500/dinov3/seed0
```

Run SLEAP inference and metrics:

```bash
bash scripts/run_sleap_eval.sh \
  outputs/sleap/train_0500/unet/seed0/checkpoints \
  "$QDMOUSE4M_RELEASE_ROOT/evaluation_sets/refonly_pose_k50_in_session_v1_valid3dfix_20260503" \
  test_100000_stratified \
  outputs/eval/in/sleap/train_0500/unet/seed0
```

Metrics include 2D error percentiles/mean, 2D PCK, mOKS, mAP, mAR, reprojection
error when calibration tooling is installed, and 3D jump-rate summaries when
triangulation is available.

## Keypoint-MoSeq Syllable Inference

Prepare release 3D trajectories, apply a trained KPMS model, and export
full-frame per-session syllable predictions:

```bash
bash scripts/run_kpms_inference.sh \
  /path/to/kpms_project_dir \
  nst50_ds2_ld15_k1e06_seed1_seed1 \
  outputs/kpms/nst50_ds2_ld15_k1e06_seed1_seed1
```

The public release config is
`configs/kpms/nst50_ds2_ld15_k1e06_seed1_seed1.yaml`. See `docs/KPMS.md` for
the explicit bodypart graph, model settings, validity masking, and syllable
annotation map.

## Gait Analysis

Build per-stride metrics from the release 3D trajectories and render the
canonical gait figures (`fig_main_canonical`, `fig_main_traces`,
`fig_individual_diffs`, `fig_syll_name_usage`, `fig_syll_name_fingerprint`,
`fig_syll_name_speed_violins`):

```bash
bash scripts/run_gait.sh \
  outputs/kpms/nst50_ds2_ld15_k1e06_seed1_seed1/syllable_bundle \
  outputs/gait \
  path/to/mouse_map.csv   # optional; omit to treat sessions independently
```

The release config is `configs/gait.yaml`. See `docs/GAIT.md` for
stride-detection thresholds, the mouse-map CSV schema, and the explicit
output layout.

## Repository Map

- `src/qdmouse4m_benchmark/prepare_projects.py`: materializes LP3D/SLEAP projects.
- `src/qdmouse4m_benchmark/train_lp3d.py`: LP3D training wrapper.
- `src/qdmouse4m_benchmark/train_sleap.py`: SLEAP-NN training wrapper.
- `src/qdmouse4m_benchmark/infer_lp3d.py`: LP3D inference wrapper.
- `src/qdmouse4m_benchmark/infer_sleap.py`: SLEAP-NN inference wrapper.
- `src/qdmouse4m_benchmark/kpms.py`: Keypoint-MoSeq release trajectory prep and syllable export.
- `src/qdmouse4m_benchmark/gait.py`: stride detection and gait figure rendering.
- `src/qdmouse4m_benchmark/evaluate.py`: common metrics for both model families.
- `configs/`: split and experiment configuration summaries.
- `scripts/`: scheduler-free shell entry points.
- `docs/`: detailed data, preprocessing, experiment, and evaluation notes.
